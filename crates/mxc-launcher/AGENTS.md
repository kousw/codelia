# Native MXC launcher

The native launcher (`codelia-mxc-launcher`) runs an admitted command with the official MXC Rust SDK (`mxc-sdk = "=1.1.0"`) on macOS arm64 (Seatbelt via the SBPL `profile` supplied by runtime) and Linux x64/arm64 (Bubblewrap via the `filesystem` policy and deny-all network policy supplied by runtime). The same binary contains the shared Unix supervisor and worker (`src/unix.rs`), with platform launch adapters in `src/darwin.rs` and `src/linux.rs`. Runtime owns tool admission, resource policy, trusted binary discovery and task accounting. [Runtime integration](../../packages/runtime/src/permissions/mxc-launcher.ts) · [Linux MXC backend](../../packages/runtime/src/permissions/linux-mxc-backend.ts) · [Architecture and qualification](../../dev-docs/specs/command-approval-reference.ja.md#mxc-evaluation)

The payload receives standard input, output and error. A separate private channel carries the request (protocol v2, `--probe-v2`, mutually exclusive `profile` or `filesystem`) and lifecycle reports. Report a verified completion only after SDK cleanup and the matching terminal report. Workload exit codes, including 125, are data. Missing reports and cleanup warnings mean the outcome is unconfirmed. All signals outside the SDK must target a process or group owned by the invocation.

Run `cargo test --locked --manifest-path crates/mxc-launcher/Cargo.toml` for the portable protocol and supervisor tests. On a macOS arm64 host, build the release helper and run the runtime native tests with `CODELIA_APPROVAL_MXC_LIVE=1`. On a Linux x64/arm64 host with `bubblewrap` and unprivileged user namespaces, build the release helper and run `CODELIA_APPROVAL_LINUX_MXC_LIVE=1 bun test packages/runtime/tests/linux-mxc-backend.test.ts` (covered in CI's `linux-sandbox` job on Ubuntu 24.04). The packed install smoke exercises macOS live MXC and verifies Linux staged packaging (`codelia-mxc-launcher` + `MXC-LICENSE.md`). Windows currently builds the protocol checks and returns 125 for an unsupported helper invocation.
Use host-native absolute paths in protocol fixtures. The decoder uses `Path::is_absolute()`, which requires a drive prefix for rooted Windows drive paths.
