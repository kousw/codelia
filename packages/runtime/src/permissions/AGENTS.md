# Runtime command approval

- The authority model is specified in [command-approval-and-auto-review.md](../../../../dev-docs/specs/command-approval-and-auto-review.md). Keep OS enforcement, request binding and UI transport in runtime.
- `shellInvocationArgs` converts an admitted source or direct argv invocation into the process argument list shared by native launch backends.
- `route.ts` implements the ordered local decision. `dispatch.ts` defers review evidence until the review route and binds once-only decisions to authority, owner and intent. Bind review evidence to the active parent run independently of intent revisions.
- A user-owned opt-in under the `confined-auto-launch` config directory delegates ordinary local parent shell launches under readonly or workspace-write. Bind the opt-in to the canonical workspace and directory identity. Recheck its revision at launch. Match hard denies, host ceilings and required analysis before dispatching a one-use launch. The global reviewer preference, reviewer readiness and saved allows are independent of this route. Interactive stdin stays outside the route; write-only `additional_write_roots` escalations (outside workspace or targeting a home dot-directory, excluding filesystem roots, Codelia config and credentials, and paths overlapping the running installation or MXC launcher) route through Auto Review when active and fall back to human confirmation otherwise.
- `home-dot-paths.ts`: when a write grant includes the user's canonical home directory (`~`), ordinary children remain writable in `workspace-write` while top-level dot-entries (`~/.*`, existing and future, plus symlink targets) and macOS `~/Library` are read-only by default in Seatbelt, Linux MXC (`buildLinuxMxcFilesystemPolicy`), Linux gVisor (`linuxRunscMountArgs`), and built-in/delegated file tools (`SandboxContext`, `file-mutations.ts`, `workspace-files.ts`). Explicitly approved `additional_write_roots` under a home dot-directory are re-opened without weakening `protectedPaths` or `readOnlyPaths`. Backends must opt in via `supportsHomeDotProtection: true`.
- A proven symlink cycle contained in direct protected HOME entries has no destination to reserve. Keep the entry names protected and continue the launch or write. Other resolution errors still prevent writes when the affected destination cannot be determined. A resolvable dangling link reserves its future destination. Linux mounts real ordinary HOME children and applies the resolved target's write scope when a shell follows a link.
- `request-receipts.ts` joins matching in-flight RPC retransmissions and retains only ID/binding hashes until the connection ends. `rpc/tool.ts` covers operator tool execution, while the dispatcher covers shell/task start admissions. Owner changes discard in-flight records and leave their IDs expired for the rest of the connection.
- `local-reviewer.ts` owns the TUI-local selection, versioned evidence and binding to existing provider authentication. SDK reviewers remain explicit adapters. Workspace enable allows confined local parent launches independently of reviewer availability. Follow and Custom also set the reviewer route. Configuration changes invalidate pending decisions. User settings are written atomically outside the workspace, or in the verified canonical default user storage when the workspace is the user's home directory (with owner, mode, ancestor, and no-redirect checks applied to that in-workspace exception; outer-workspace configs keep directory-level owner/mode checks). Review never grants files, outbound network or billing authority to a tool.
- An unselected workspace uses manual approval where needed. If an observed active workspace setting becomes unverifiable, stop the launch with `confined_launch_config_unavailable`. Startup and `/auto-approve status` also report `confined_launch_config_unavailable` in fresh processes when an existing workspace launch file cannot be verified (distinct from absent or explicitly disabled files). Keep startup and status reporting independent of the reviewer issue. Only allow a known literal inspection to clear an indirect deny classification if the actual system executable can be bound and rechecked before launch.
- Unsupported routes and unavailable authentication use ordinary confirmation when detected before review. A Steer enqueue and its first application each advance approval intent. Historical archive failures are scoped to the evidence reference so a repaired reference can be reviewed.
- Evaluate hard denies independently of representative risk labels. When a user can resolve a hold, the compact shell picker displays the command and choices. Keep the confirmed rule scope visible when saving, with the full command, reason and authority in scrollable details. Run once and skip do not invoke a rule-proposal model. Only an explicit setup choice can generate a candidate, which must bind to the original launch and be confirmed by the user before saving. Noninteractive review holds retain classified outcomes. A reviewer can request a user decision without approving the pending invocation. `approval-history.ts` records raw RPC user input with canonical workspace and cwd. Earlier approvals supplied through `shell.approval_context` must resolve to original conversation IDs in the same scope. Keep archive provenance, proposed effects, launch binding, and Steer invalidation independent of model-supplied claims.
- For `ask_user`, accept only the enumerated missing-item code as agent-facing clarification. The next user message or applied Steer supplies authority. Keep matched and unverifiable shell denies distinct. Keep ordinary URLs and paths verbatim in evidence for the reviewer.
- `reviewer-models.ts` is the single built-in registry for review model selection, fixed destinations and account/data disclosures. Follow resolves the active chat provider for each run. Technical contract verification permits experimental registration with an explicit quality label. Compare labeled decisions before promotion. All eight built-ins have a fixed provisional reviewer. OpenAI OAuth uses only the fixed, bounded Codex SSE route. Other built-ins use their configured provider API key. Follow uses the real admitted chat Agent's built-in provider. Custom and legacy settings pin the route. Named Responses endpoints never resolve a reviewer. OpenRouter uses its registered fixed upstream and requires matching route evidence.
- The review specification's offline evaluation uses the runtime dispatcher's decision parser. Elapsed time is an observation. Keep deterministic no-send cases out of model-quality measurements.
- `tool-approval.ts` wraps exact runtime registrations. Toolbox names and provider hints carry no authority. Internal tools use their own admitted path only when the runtime factory owns that exact object.
- In local TUI `workspace-write`, the registered `apply_patch` can use the existing workspace grant for a patch consisting entirely of independent file additions and updates. Bind all targets and consume the approval after patch preparation, before the first write. Deletes, moves and host-provided authority follow the existing routes.
- Bind `apply_patch(dry_run=true)` as a read-only, workspace-scoped inspection. Reject an unsupported protected move into an earlier vacated destination before any write. Image exports use the approval-bound sandbox and cancellation signal after reading the original artifact.
- Native TUI helpers use explicit runtime registrations for the five fixed UI operations on the native launcher connection. Generic client registrations continue through their configured approval policy.
- Stdio MCP startup and the explicit CLI probe use the same confined launcher. Validate configured environment keys up front, bind the configuration to the request, and transfer the values only to the confined worker over private stdin. The launcher and its authorization preview receive no environment values.
- A local user's remembered built-in tool permission is workspace-scoped in the user-owned projects store. Keep it independently listable and revocable; shared-config trust and tool invocation never grant paid effects or additional filesystem rights.
- `shell-approval.ts` binds the source or direct argv, chooses a profile and passes a one-use launcher to managed tasks. `policy-index.ts` refreshes cached configuration on revision. `launch-rules.ts` persists exact or displayed argv-prefix rules separately from resource grants. `local-permission-allows.ts` resolves the user and trusted project config for TUI-local admissions. Preserve legacy trusted scopes and explicit project revocation. Apply denials and revalidate the policy at dispatch.
- Derive suggested rule words and their sharing checks from the bound invocation. Effect classification may normalize a tool name or recognize test selectors. Keep the executable identity and original invocation form when reusing a rule. The shared model prompt keeps the words that select the operation and requests exact matching when the rule format cannot express that boundary.
- `shell-path.ts` preserves the launcher's command `PATH` or the SDK host's exact `RuntimeHostAdapters.shellPath`, including relative and empty entries. A saved rule binds the selected executable and exact arguments. Recheck the binding and preserve the approved Bash source or direct argv at launch. Normal commands retain the original `PATH` when that search order cannot be bound. The packaged MXC helper and the Linux supervisor resolve independently of command `PATH`.
- Use a fixed system `PATH` and the default source resolver in tests that exercise system command binding. Ubuntu can resolve coreutils utilities to paths outside `/usr/bin` and `/bin`; direct argv tests must assert the route for the resolved executable.
- Confined POSIX launches use the login `HOME` (read-only outside existing grants, with private scratch `TMPDIR` and `XDG_CACHE_HOME`) and expose only the validated Rust toolchain directories from `toolchain-homes.ts` in addition to the existing environment. They receive no extra filesystem access. The full-access worker forwards explicitly configured, validated Rust directories and uses the login HOME for Rust defaults when they are unset. Bind the directory choices to saved approvals and serialize only the named fields (`home`, `cargo_home`, `rustup_home`) in MXC helper protocol v3 (`--probe-v3`). Non-system executables use ordinary review or confirmation. For confined saved and handwritten rules, a multi-link executable must meet the root-controlled shared executable check or account for every hard link in its canonical parent outside writable and masked paths. Recheck at admission and consumption. Keep this check separate from the system executable inspection shortcut.
- When privacy prevents review submission, present the classified reason for local one-time confirmation. Preserve the invocation, existing authority, sandbox and cancellation checks. Never turn local permission into permission to share the evidence. Temporary `review_unavailable` suppresses immediate repeats and expires after 15 seconds.
- Use the inspection shortcut and the bounded full-access review scope only when every operation uses a fixed Bash builtin or resolves to the corresponding system executable. Commands whose executable identity cannot be confirmed retain the ordinary confined review or confirmation path. Recheck the binding before launch.
- An SDK shell backend can declare `supportsCommandBinding: true` only if it preserves the resolved direct executable, selected cwd, native `PATH`, and fixed Bash lookup without startup hooks. A wrapper can forward the declaration when it forwards the invocation and protection unchanged. Backends without the declaration use ordinary review or confirmation for bound read commands.
- The POSIX source launcher requires a root-controlled Bash. On Linux it checks the NixOS system profile and conventional `/bin/bash` and `/usr/bin/bash` locations. The source launches the resolved absolute executable with fixed options and rechecks the binding. Command `PATH` does not participate. The Linux sandbox backend still has independent helper and host qualification requirements. Native macOS Seatbelt tests that explicitly spawn `/bin/bash` require that system binary.
- Keep technical Auto approve failures classified through provider, dispatch and the owning run journal. Persist only bounded diagnostic fields; never include credentials, raw errors, provider bodies or the review packet in the failure record.
- For pre-send evidence holds, report the failed check and its field. An offset refers to the original source only when the checked text has the same representation. Keep shell launch, review submission and the model decision distinguishable in caller-visible results.
- On the fixed Codex OAuth route, accept a missing response MIME declaration only through the bounded SSE parser and the ordinary decision validation. Keep explicit media-type mismatches and incomplete streams fail-closed. The opt-in macOS live check and observed outcomes are documented in the [review reference](../../../../dev-docs/specs/command-approval-reference.ja.md#codex-oauth-の実モデル動作確認).
- The inspection parser accepts literal quoted long-option values and flat literal brace lists in finite `for` loops. Numeric line-print `sed`, bounded `head`/`tail` and ordinary file listings are local reads. Git inspection remains eligible for Auto approve under the investigation profile because Git configuration can invoke helpers.
- `shell-backend.ts` selects the explicit adapter or the platform backend (macOS Seatbelt, or Linux MXC Bubblewrap by default with `CODELIA_LINUX_SHELL_BACKEND=gvisor` selecting rootless gVisor). The selected launcher must support the protection profile and any invocation-specific restrictions through dispatch. Alias checks cover the explicitly indexed protected files and directories. The shared file tools use the same configured protected paths and bind existing file descriptors. Directory creation, removal and move use the protected broker in `../sandbox/file-mutations.ts`.

- `workspacePathProtection` keeps inaccessible paths separate from the Git marker, Git directory and common directory that workers can read. A protected SDK backend must explicitly opt into `supportsReadOnlyPaths` only when it can deny writes to those paths and their aliases. A path that also matches the inaccessible list remains inaccessible.
- Local `projects.json` may add absolute `protected_paths` under `default` and the canonical project key. Use their union for the runtime lifetime. A home-scoped workspace reads and updates its own canonical, owner-verified user policy in the runtime's reserved storage (with ancestor and no-redirect checks). Reject other workspace overlaps, arbitrary overrides, and redirects. When project `.codelia/config.json` resolves to the same file as global `config.json`, treat it once as the `global` layer and reject `project`-scoped config/rule writes. `RuntimeHostAdapters.approvalProtectedPaths` supplies the host ceiling independently. Local `full-access` shell uses the OS user account, while built-in file tools continue applying the configured paths. A host adapter is responsible for applying its mandatory shell ceiling.
- Reserve the entire project `.codelia` tree by path. Resolve project configuration links, including resolvable dangling targets, and check existing aliases. Index concrete authority files in runtime storage separately. Keep runtime cache, session history and legacy lane worktree contents outside project alias discovery.
- Ordinary reads follow OS file access and the configured private paths. Kernel device and IPC policy is independent. Keep Codelia-managed paths write-protected. Index Git, project policy, explicit host paths, and concrete runtime authority files for alias checks. Do not traverse the runtime's whole history or cache. External review has a separate private-path check before transfer.
- External review keeps explicitly private user or SDK resources and Codelia-owned authentication and approval files local. Check credential values and explicit sharing restrictions independently of shell grammar. Development filenames and directory conventions do not carry a sharing decision by themselves.
- Goal continuations inherit confirmed Steers for the same goal from its reservation state. After an objective edit, present earlier Steers before the current objective and later Steers after it. The TUI bang evidence projection uses the user's text after leading serialized result frames for both submission and Steer. Embedded result data never supplies authorization.
- Protected patch deletes and moves require regular directory entries. Reject a symbolic link in the named entry and preflight repeated paths, shared inodes and ancestor conflicts before executing any change.
- Standard macOS TUI `workspace-write` shell admission permits existing links from the canonical Git common `objects` directory for a verified ordinary repository or linked worktree. Skip that directory only in the shell's read-only alias scan. Bind and recheck its directory identity, and keep the strict scan if the layout is uncertain or stronger protected paths overlap. Direct metadata restrictions, fixed tools' target checks, and the SDK contract still apply.
- A direct link in the common Git `hooks` directory can coexist with the objects exception only when its current regular-file target is covered by the same read-only and alias checks. Other unresolved metadata links keep the strict scan.
- Seatbelt pins writable ancestors of inaccessible and read-only paths. Built-in file entry points use `resourceContainsPath` for policy names. Consult filesystem identity for existing entries and reserve missing equivalents when the directory's name resolution cannot be established.
- Direct and MXC Seatbelt allow signals to processes in the same sandbox and Mach lookup of the exact `com.apple.system.opendirectoryd.libinfo` service for account resolution. Native process checks cover `whoami`, Node's `os.userInfo()`, `proc_name` for a child, and its `SIGTERM` exit. On macOS 26.2, the system's set-user-ID `/bin/ps` fails to start with `EPERM` even for explicit worker and child PIDs.
- The TUI-local macOS directory mutation broker uses a fixed helper. Build the helper argv and exact Seatbelt write permissions from the same selected operands. New file contents go through the private input pipe. Parent and delegated file operations share this broker, including when the general development shell cannot satisfy its protection profile. Explicit SDK shell backends retain their existing contract.

- On macOS arm64, the TUI-local host can select MXC with `CODELIA_MAC_SHELL_BACKEND=mxc`; SDK hosts can supply `createMacMxcShellBackend()`. The default remains direct Seatbelt. On Linux x64/arm64, `LinuxMxcBackend` (`linux-mxc-backend.ts`, `exactLaunchBindingId = "codelia.linux.mxc/v1"`, SDK `createLinuxMxcShellBackend()`) is the default backend using `crates/mxc-launcher` (protocol v3, `--probe-v3`) with MXC `Containment::Bubblewrap` (deny-all network, private `/tmp`/`/run`, narrowed readable roots excluding `/var/lib` and `/nix/var`, refusing `/tmp` as a write root, allowing socket/FIFO `protected_paths`, verified root-owned `bwrap` and system `sh`, system-fixed `PATH=/usr/bin:/bin` for `bwrap`'s `sh -c` wrapper with workload `PATH` exported before `exec`, home-dot hard-link alias checks, pre-launch frame-size checks, anchored mutable ancestors, no `supportsAbsentPathDenial`); `CODELIA_LINUX_SHELL_BACKEND=gvisor` selects `LinuxRunscBackend` (unrecognized values fail closed). Resolve the native helper relative to the runtime installation (`@codelia/tui-{darwin-arm64,linux-x64,linux-arm64}`), outside the agent's mutable project, and protect the resolved launcher, `bwrap`, and `sh` paths from `additional_write_roots`. Check both process exit and the private control channel before reporting verified cleanup. See the [native integration and host evidence](../../../../dev-docs/specs/command-approval-reference.ja.md#mxc-evaluation).
- One-command escalation (`shell` input `escalation: "unsandboxed"`): `createShellAuthorizer` takes a separate `escalationBackend` (the TUI-local runtime supplies `UserShellBackend` only when no custom shell/approval adapters or operator protected paths are configured). The launch uses profile `full-access` with the resource `UNSANDBOXED_SHELL_RESOURCE` (`invoke shell.unsandboxed`) in the ceiling (honoring any host `workspaceWrite: "forbid"` even in `readonly`) and never in the grant. In `workspace-write` with granted workspace writes, an active Auto Review model, no user `protected_paths`, and a parsed, non-destructive, non-indirect command (`!effects.hasDestructive && !effects.indirectExecution`, including independent destructive checks on network commands and `osascript`, and `opaqueReason` limited to `undefined | "unrestricted_program"`), `routeApproval` routes escalation through Auto Review (with interactive human fallback on deny/inconclusive/failure); `readonly`, ungranted `workspace-write`, no-reviewer workspaces, `protected_paths`, destructive (local or remote), indirect wrappers, unbound directory changes, and opaque commands remain strictly human-confirmed. `dispatch.ts` keeps the interactive shell prompt without rule-save choices, fail-closed indirect-execution deny verification and path-target identity binding apply, and `UserShellBackend` scrubs shell/loader startup hooks (`loginUserEnvironment`) before inheriting the login environment. Saved/configured allows and confined auto-launch never apply. The structured confirmation (`runtimeApprovalDispatcher`) marks only this approval with `ui.pick.request` `escalation: "unsandboxed"`, including the Auto Review human fallback. `createShellAuthorizer` passes `escalation: "unsandboxed"` (plus `protectedPathsEnforced: false` with configured protected paths) to `dispatch`, which forwards them on `Confirmation`; the dispatcher also requires subject `shell` and the `invoke shell.unsandboxed` resource, so a host tool whose name collides with that resource is never marked. Derive titles, labels and markers from these structured fields, not preview text.
- Read-only Auto Review inspection (`review-inspector.ts`): `LocalAutoReview.adapter` runs a bounded async multi-round structured-output loop (`reviewerWire("inspect_review")`, stripping numeric `minimum`/`maximum` bounds for cross-provider structured output compatibility, max 3 rounds with terminal-only final round, max 4 requests/round, max 8 total inspections, max 14 KiB inspected data, max 24 KiB follow-up packet) across all 9 stateless provider adapters. `read_file`, `list_dir`, and literal `grep` run strictly in-process inside the pinned canonical workspace, reject dangling symlinks and hard links aliasing protected inodes (`isProtectedAlias`), check raw unclipped lines for credentials/privacy/provider tokens before clipping, bound directory/entry traversals with event-loop yields, label outputs as untrusted data (`inspected_data_untrusted`), refuse `allow_once` on unsandboxed local workspace executables until fully read without truncation, and record fd-derived file identities plus directory entry digests and all scanned grep files in `InspectedBinding` entries re-verified synchronously in `LocalAutoReview.adapter.stillApproved(request)` right before `backend.launch(...)` to prevent TOCTOU swaps.
- Git write scope: `workspacePathProtection(..., { gitWrites: true })` (gated behind explicit `allowGitWrites` — enabled on local TUI development shells with `extraWrite.length === 0` and backends declaring `supportsAbsentPathDenial: true`, currently macOS Seatbelt/MXC; SDK hosts default to false) opens Git writes ONLY for a repository whose `.git` marker lives directly at the workspace root (verifying non-symlink bidirectional `worktrees/<name>/gitdir` back-pointers for linked worktrees; parent repos and nested `.git` pointers under `cwd` stay read-only). `gitWriteScope()` traces full multi-hop symlink chains, protects `config`, `config.worktree`, `hooks/`, `commondir`, `gitdir`, `objects/info/alternates`, `remotes/`, `branches/`, `modules/`, `rebase-merge/`, `rebase-apply/`, `sequencer/`, existing linked-worktree entries, and `include.path`/`includeIf.*.path`/`core.hooksPath` targets parsed from repo/worktree configs (failing closed on symlink cycles or unparseable configs), and reports `gitWriteRoots` to Auto Review (`review-evidence.ts`) plus absent `gitProtectedPaths` ancestor create-protection in Seatbelt. Backends without `supportsAbsentPathDenial` (Linux gVisor) and built-in file tools keep `.git` read-only. Seatbelt allows pseudo-terminals created in the sandbox (`com.apple.sandbox.pty` extension) and ioctl only on pre-existing ttys. Live coverage: `tests/sandbox-git-writes.test.ts` (`CODELIA_APPROVAL_MAC_LIVE=1` / `CODELIA_APPROVAL_LINUX_LIVE=1`; Linux runs in CI).
