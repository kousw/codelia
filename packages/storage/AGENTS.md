# @codelia/storage

Concrete persistence stores and storage layout (`~/.codelia` default; `CODELIA_LAYOUT=xdg` splits config/cache/state).

## Policy & Credentials (`paths.ts`, `projects-store.ts`, `user-storage-boundary.ts`)

- Create `credentials/` with `0700` on POSIX and owner/SYSTEM DACL on Windows (general directory init does not run ACL tools).
- `ProjectsPolicyStore`: combines `default.protected_paths` and canonical project `protected_paths`. When workspace is `~`, reads honor owner-verified configured storage under the active layout (so custom `XDG_CONFIG_HOME` policies are never dropped), while writes target only canonical default reserved storage (`~/.codelia` or `~/.config/codelia` independent of `XDG_CONFIG_HOME`) after owner, mode, ancestor, and no-redirect checks; checkout overlaps, home-directory redirects, and arbitrary overrides inside an active workspace are rejected. `isSameConfigFilePath` compares canonical paths and `dev`/`ino`; `isTrustedGlobalConfigLocationSync` gates global provenance for workspace-resident `config.json`. Share lock between sandbox and project-allow writers; `trust_project_allows: false` overrides legacy trust; write atomically (`0600`). Missing POSIX owner verification supplies no authority and stops startup if private paths are configured.
- Credential storage v2 (`auth-lock.ts`, `atomic-file.ts`, `windows-acl.ts`, `credential-migration.ts`, `credential-backend.ts`, `macos-keychain.ts`, `auth-schema.ts`, `mcp-auth-store.ts`):
  - `withAuthStoreLock` coordinates provider + MCP auth under `<configDir>/credentials/.auth-store-lock.sqlite` (35s wait, separate from `projects-store.ts` 1s lock); `writeFileAtomic` writes `0600` temp + `fsync` + rename.
  - `coordinateCredentialBackendUnlocked` implements global-only `auth.storage` (`auto|keyring|file`, env `CODELIA_AUTH_STORAGE`), write-ahead `storage-state.json`, split-brain prevention on locked Keychain, all-direction `CredentialConflictError`, and two-phase migration (`keep_keyring` requires present non-empty Keychain before deleting file/legacy copies).
  - `MacOsKeychainClient`: invokes Apple-signed `/usr/bin/security` directly (`security -i`, 1,800-byte raw chunks, max 64 chunks / 115,200 bytes on both write and read) using `codelia.auth` / `codelia.mcp-auth` and `codelia-<sha256(canonical(configDir)).slice(0, 16)>`. Writes require a confirmed root read; single chunks use `cb1:1:<base64>`; multi-chunks alternate A/B slots (`cb2:<slot>:<total>.<sha256>`) with read-back verification; backward-compatible reads accept `cb2`, `cb1`, raw UTF-8 JSON, and hex-encoded JSON; logout deletes `0..63` in both A/B slots and propagates errors; timeouts direct users to `codelia auth authorize-keychain`.
  - `McpAuthStore`: persists v2 endpoint/issuer/client-bound tokens via locked `update()`, dropping unbound legacy v1 entries with `mcp_reauth_required`.

## Sessions, Archives & Retention

- **Originals & checkpoints (`messages/`, `contexts/`, `conversation-archive.ts`)**: `messages/` is append-only byte-for-byte original history (never replace with compacted/trimmed views); await `appendMessages` before Agent admissions; migrate active view to `contexts/` before switching index archive version under SQLite guard. Byte-offset message IDs preserve UTF-8/CRLF boundaries and reject torn tails; search/read outputs are bounded and omit opaque provider payloads. Historical shell approval reads raw archived user input plus `session_approval_steers` canonical applied events only.
- **Run logs & maintenance (`run-log-*.ts`, `session-run-index.ts`)**: Normal logs omit full requests/responses/raw tool output; full dumps under `sessions/diagnostics/` require `CODELIA_DEBUG=session-dump` (may expire); compact `llm.usage` persists separately under `<storage-root>/usage/`.
  - `run-log-archive.ts` / `run-log-retention.ts`: preserve conversation/lifecycle bytes and canonical usage (correlating request seq/provider/name even after large inputs before dropping diagnostics; header fallback only); verify decoded projection hash/length; keep final writer/pin/source checks and publication synchronous inside one index guard (never insert an async step before source removal); new plain->gzip publication uses exclusive `linkSync` (destination conflict preserves both files, distinct from atomic replacement of legacy gzip); pinned sessions and live writers block automatic archive conversion and diagnostic expiry; never collect originals, active checkpoints, index, references, usage, or task data.
  - Live-writer markers (`run-log-files.ts`, `process-identity.ts` using C/UTC env while runtime task callers keep the legacy default environment): remove reused-PID markers only when saved/current identities demonstrably differ and marker is unchanged (legacy/unknown identities retain liveness protection).
  - `SessionStateStoreImpl` opens SQLite lazily on first DB use, migrates legacy `sessions/state/<id>.json` on load, stores `workspace_root`, and indexes `state.db.session_runs` (one-time backfill fallback only; never scan run headers in new code).

## Artifacts, Cache & Tasks

- `FileAttachmentStore` (`sessions/attachments/`): publishes batch ownership marker, verifies hash blocks on range reads, and delegates copied visual inputs to `ImageArtifactStore` with private owner checks.
- `ImageArtifactStore`: immutable PNG/JPEG originals (preserving original bytes, MIME, and extension), bounded no-follow reads (`image-png.ts`), admission-time JPEG views (`image-model-view.ts`, lazy `sharp`, quality 90 4:4:4; `resolve` obeys stored descriptor and never upgrades legacy refs; `read` always returns originals), inline attachments via `image-size` header validation (filenames from MIME only), max 16 refs (`IMAGE_REFERENCE_MAX_COUNT`), no automatic deletion/TTL.
- `ToolOutputCacheStoreImpl`: grapheme-clipped bounded previews + physical-line `readLine`. `TaskRegistryStore`: per-task JSON files under `tasks/` preserving `key`/`label`/`title`/`working_directory`.
