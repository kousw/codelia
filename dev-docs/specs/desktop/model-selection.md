# Native provider and model recovery

Implemented subset, 2026-10-07. The provider/model chooser stays next to the composer. A configured unsupported provider does not hide the supported provider buttons. Native lists built-in models with explicit `model.list {provider,catalog_only:true}`; this route reads no config/auth and makes no metadata/provider network request. OpenRouter has no built-in usable catalog here: an empty list explicitly offers another provider, rather than silently fetching or changing authentication. Credential availability is not probed; ordinary runtime admission reports missing credentials when the user sends.

Listing is not selection. `ChooseModel` attaches provider/name to the selected conversation in memory without an RPC/config/auth write. Send passes an optional negotiated `run.start.model`. Runtime validates the exact object/provider/known static model before admission, applies it after selecting the fresh/resumed target thread, invalidates the Agent cache and saves it in that thread's existing model override metadata. Preflight failure restores the previous Agent/model/session. Another thread's model/history/config is not changed. Clients without `supports_run_model` cannot use this explicit choice; reconnect/update is required. Legacy callers omitting the parameter keep their prior behavior.

Unsent model choices remain in memory; only current unsent text uses the draft store. After a successful run, the model override persists with that session. No submitted work is automatically replayed.

Native model readiness gates both buttons and shared Send admission, including keyboard Send. Catalog errors have a separate recovery message. The header distinguishes connected-without-model from ready-to-send. Latest catalog request identity rejects stale provider responses. A chosen model is not an assertion that sign-in or provider connectivity succeeded.

Child agents use `task.list {kind:subagent}` and native kind filtering, so shell/tool jobs are not presented as delegated agents. The runtime's existing owner-session task scope remains authoritative. Parent Stop still leaves children running. Same-basename open folders show a distinguishing path suffix with the full path available on hover. Related worktrees show folder/current selection and branch separately; unknown status is not clean. Internal creation diagnostics are collapsed behind Details; unsupported checkout setup disables creation, without running setup. Navigation scrolls if content exceeds the window. Changes stays optional.

Regression evidence: unsupported home config with explicit static recovery/no auth/config access; exact thread choice/late catalog response/Send guards; failed admission rollback and old-session preservation; headless narrow provider reachability/Japanese draft retention/only actual subagents. Current native pixels, provider-auth/OS connected model switch, IME and real-provider calls remain unverified.
