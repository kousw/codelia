# Current native composer drafts

Status: **Implemented local subset**, 2026-10-07. Native OS/IME/restart pixels remain unverified. No model run or tool side effect is replayed on recovery.

## Boundary and identity

`drafts.rs` is a pure snapshot of current nonempty composer text/title by exact thread ID. It excludes transcript/stream rows, last submitted prompt, tool output, approval/prompt answers and credentials. `draft_controller.rs` coalesces projection changes; `draft_store.rs` owns a background worker and all filesystem/Git observation. Views call the application Send/Clear commands through the workspace adapter. Existing runtime sessions and subagent orchestration retain execution authority.

Native storage follows the normal Codelia state root: `~/.codelia` by default; with `CODELIA_LAYOUT=xdg`, `$XDG_STATE_HOME/codelia` or `~/.local/state/codelia`. Explicit native validation environment overrides use the same root as the fixture runtime. The native store is local and independent of runtime connectivity.

Path: `<state-root>/desktop/drafts/<project>/<checkout>/current.json`. Private storage project IDs hash canonical common Git directory plus device/inode identity; linked Git checkouts share the project. Checkout IDs also bind the canonical selected folder and its device/inode identity. Ordinary non-Git folders use their own physical folder identity. Broken/unreadable Git metadata does not silently become a non-Git scope. These private 64-character IDs are not the runtime's public project ID. A live worker pins identity and revalidates before/after a replacement write. Moving/replacing a root creates a different namespace; it never loads or writes old text into a replacement checkout.

Unbound draft IDs use UUIDs, including the initial native workspace draft, so input typed while startup load is in flight cannot collide with a saved draft or another app instance. First accepted runtime admission migrates the conversation to its returned session ID. Saved session drafts require history replay before sending; their text does not itself resume a run. Empty draft tabs are memory-only.

## Save and recovery contract

- Only one version-1 current JSON record per physical checkout; at most 64 nonempty thread drafts, 256 KiB UTF-8 text each, 4 MiB aggregate text/title, 512-byte titles and 256-byte thread IDs. Serialized/read bytes are additionally bounded. Oversize input stays in memory with a save error; no truncation or overwrite of the prior record.
- Input changes set a dirty marker without disk I/O or serializing text on the GUI thread. Save coalesces after 250ms idle, or after two seconds of continuous editing. There is one acknowledged worker save in flight, plus a bounded command queue. Acknowledgement follows file and directory fsync. Newer text remains dirty until its own acknowledgement.
- Missing data is empty. Recovery merges saved drafts into unique local threads without overwriting newer startup typing. Selection may restore a saved draft, but no send, model, approval response or tool action occurs. Recovering a persisted session draft marks history as needing replay.
- JSON strictly validates version, physical identity, fields and bounds. Corrupt/foreign/oversized/unreadable data fails visibly and is preserved; never reset it implicitly. Neither text nor title appears in diagnostic logs. Diagnostics use generic static messages; plaintext draft content remains only in the private draft file and normal UI.
- New directories use 0700 and new files 0600. An OS advisory lock serializes writes and releases after abrupt process exit. Revision comparison rejects stale app instances. Save writes/fsyncs a new temporary file, revalidates scope, atomically renames and fsyncs the directory. Only one owned pending file exists; uncommitted pending data is never restored/replayed and is removed under the lock on valid recovery. No backup/revision history is retained.

Send stages an exact thread/action and requires durable removal of that draft before dispatching `run.start`. Save failure restores input and sends nothing. **Cancel send** while saving retains text and never dispatches the cancelled action; a late consumption acknowledgement cannot release a newer action or a different thread's send. Disconnect/reconnect and normal quit cancel staged sends; no automatic replay. An explicit rejected run admission restores only its owner's text. Loss after actual dispatch remains an unknown runtime outcome and is not converted into an automatically resendable draft.

**Clear draft** commits removal before clearing the UI; it follows the same pure application route and never invokes a model. Deleting all text by keyboard is a normal debounced empty save. Normal quit flushes current drafts before runtime cleanup. Failed flush leaves the window/input open, keeps the original bound worker and reports the failure; **Quit without saving** is a separate explicit user action. Early quit before load completes merges unseen committed drafts with new local text instead of replacing them.

## Verified and remaining limits

Rust unit/physical-file tests and headless GPUI controls cover: two threads; real linked Git worktrees; canonical aliases; replacement roots; foreign record refusal; stale writers; corrupted/oversized records; write failure; periodic/coalesced saves; early/normal quit; failed quit retaining input; saved Japanese restore/Clear; cancelled repeated sends; and rejected admission restoring its owner. A test-only child exits without unwinding after pending-file fsync/before rename and after a committed clear; a new process/store observes the correct committed state and released lock. Test roots are disposable and no process-kill API is used by these tests.

Only acknowledged text is crash-durable. Forced termination can lose edits still waiting for the coalescing interval or disk acknowledgement. Keyboard clear follows that same rule; explicit Send/Clear waits for durable removal. A crash between durable consumption and runtime acknowledgement does not restore/resend submitted text; inspect canonical runtime history and workspace changes. Crash-safe reconciliation of arbitrary tools, task leases and archive/restore/integration remain outside this feature. OS-native pixels, Japanese IME, actual app quit/reopen and low-memory/1–4–8 task measurements remain unverified.
